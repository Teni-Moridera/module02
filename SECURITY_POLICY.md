# Политика безопасности БД «Библиотека»

## 1. Область действия

Документ определяет политику доступа, защиты данных и контроля целостности для базы данных `practice6` (тема: библиотека).

---

## 2. Разграничение доступа

### 2.1. Роли и права

| Роль | Описание | SELECT | INSERT | UPDATE | DELETE |
|------|----------|--------|--------|--------|--------|
| **admin_role** | Администратор | ✓ все | ✓ все | ✓ все | ✓ все |
| **librarian_role** | Библиотекарь | authors, books, readers, loans, change_log, audit_log | authors, books, readers, loans | authors, books, readers, loans | loans |
| **reader_role** | Читатель | authors, books, readers | — | — | — |
| **auditor_role** | Аудитор | change_log, audit_log | — | — | — |

### 2.2. Пользователи

| Пользователь | Роль | Назначение |
|--------------|------|------------|
| db_admin | admin_role | Полное администрирование |
| librarian | librarian_role | Работа с каталогом и выдачами |
| reader_user | reader_role | Просмотр каталога |
| auditor | auditor_role | Просмотр журналов изменений и аудита |

### 2.3. Принцип наименьших привилегий

Каждому пользователю выдаются только те права, которые необходимы для выполнения его функций.

---

## 3. Защита данных

### 3.1. Резервное копирование

- **Инструмент:** `pg_dump`
- **Формат:** custom (`-F c`) с сжатием
- **Частота:** ежедневно (рекомендуется через cron/Task Scheduler)
- **Скрипты:** `05_backup.bat` (Windows), `05_backup.sh` (Linux)
- **Хранение:** каталог `backups/`, не менее 7 последних копий

### 3.2. Контроль целостности

- **Внешние ключи:** все связи между таблицами через FK с `ON DELETE RESTRICT`
- **CHECK-ограничения:** `quantity >= 0`, `status IN (...)`, `return_date >= loan_date`
- **Периодическая проверка:** скрипт `06_integrity.sql` для выявления «битых» ссылок

### 3.3. Аудит действий

- **Таблица audit_log:** фиксация удалений и регистрации новых читателей
- **Таблица change_log:** полный журнал INSERT/UPDATE/DELETE по основным таблицам
- **Функция audit_action():** ручная запись событий из приложения

---

## 4. Триггеры

| Триггер | Таблица | Назначение |
|---------|---------|------------|
| tr_*_changelog | authors, books, readers, loans | Запись в change_log при любом изменении |
| tr_loans_availability | loans | Запрет выдачи при отсутствии свободных экземпляров |
| tr_loans_return | loans | Автоустановка status='returned' при return_date |
| tr_audit_* | authors, books, readers | Дополнительная запись в audit_log при DELETE/INSERT |

---

## 5. Пароли

- Пароли задаются при создании пользователей (скрипт `02_users_roles.sql`)
- **Рекомендация:** заменить демо-пароли на стойкие перед эксплуатацией
- Хранение паролей: только в защищённом хранилище (менеджер паролей, секреты CI/CD)

---

## 6. Порядок развёртывания

1. Создать БД: `CREATE DATABASE practice6;`
2. Выполнить скрипты по порядку: `01_schema.sql` → `02_users_roles.sql` → `03_triggers.sql` → `04_audit.sql` → `07_demo_data.sql`
3. Настроить резервное копирование по расписанию
4. Регулярно проверять целостность (`06_integrity.sql`)

---

## 7. Ограничения

- **PostgreSQL:** ТЗ рекомендует SQLite, но SQLite не поддерживает пользователей, роли и GRANT. Для выполнения всех требований используется PostgreSQL.
- **Сетевая безопасность:** настройка `pg_hba.conf` и firewall выходит за рамки данного документа.
